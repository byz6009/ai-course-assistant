# 代码风格规范

Python 使用四空格缩进、`snake_case` 函数和变量、`PascalCase` 类名；前端 Vue 单文件组件使用 `<script setup>`，JavaScript 使用两空格缩进、`camelCase` 变量与函数。JSON 接口字段沿用已有 `camelCase`。沿用既有页面配色与组件风格，避免无关重构。

业务模块按职责分离：字幕解析不访问数据库；摘要适配器不修改学习任务；仓储负责事务和版本；HTTP 层负责状态码与输入边界；Vue 页面调用 API 并处理加载、失败和空状态。

用户输入需校验类型、长度、来源及范围。SQLite 使用参数化语句；事务和连接生命周期分别管理，`with db` 不等于关闭连接。异步写入以数据库约束保证去重，不能只依赖禁用按钮。

前端只通过文本插值呈现字幕和模型结果，不使用 `v-html`。请求需有超时；不在没有成功响应时标记完成。切换历史版本时禁止对尚未加载完成的结果进行确认或编辑。列表与查询使用稳定 ID，避免组件重新排列后串课。

错误信息面向用户说明下一步，不能包含模型密钥、外部服务完整错误正文或原始请求。模型配置由后端管理，支持软件设置页及既有环境变量；密钥不回显、不入 Git。生成内容与本地摘录、人工编辑分别标识。

测试优先覆盖用户可观察的行为：格式边界、来源合法性、持久化、重复点击、旧版本保留、并发与超时、浏览器全流程。新增代码通过 `npm test` 和 `npm run build`；核心页面运行 `npm run test:e2e` 并检查截图。CI 配置同时测试 Windows 与 Linux，远端 CI 尚需实际提交后观察。

提交信息应写明行为与原因，避免仅写 fix/update。按既有团队约定，AI 可以准备改动与说明，最终 commit、push、PR 和人工评审由组员完成。
